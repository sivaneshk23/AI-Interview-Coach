# AI Interview Coach Knowledge Base

## Purpose

This knowledge base supports an AI-powered Interview Trainer Agent.

The system prepares candidates for technical, behavioral, HR, managerial,
situational, case-study, role-specific and mixed interviews.

The knowledge base must be treated as supporting evidence for question
generation and candidate preparation. It must not invent company policies,
job requirements, candidate experience or interview processes.

---

# 1. Interview Types

## Technical Interview

Technical interviews evaluate job-specific knowledge, problem-solving,
implementation ability, fundamentals, practical understanding and the ability
to explain technical decisions.

Common areas include:

- Programming
- Data structures
- Algorithms
- Databases
- SQL
- Python
- Java
- Machine learning
- Artificial intelligence
- Data science
- Data analytics
- Cloud computing
- Cybersecurity
- Software engineering
- Testing
- APIs
- System design
- Data visualization
- Statistics

Questions should match the target role and candidate experience level.

---

## Behavioral Interview

Behavioral interviews evaluate how candidates have handled situations,
problems, teamwork, conflict, failure, leadership and responsibility.

Useful response structure:

STAR:

- Situation
- Task
- Action
- Result

Candidates should provide concrete examples rather than generic statements.

---

## HR Interview

HR interviews may evaluate:

- Communication
- Motivation
- Career goals
- Strengths
- Weaknesses
- Teamwork
- Adaptability
- Work preferences
- Professional behavior
- Motivation for the role
- Understanding of the organization

The system should avoid inventing company-specific HR policies.

---

## Situational Interview

Situational questions present hypothetical workplace scenarios.

Examples:

- Handling a production failure
- Managing conflicting priorities
- Dealing with an unhappy stakeholder
- Handling incomplete requirements
- Working under a deadline
- Resolving disagreement with a teammate

Evaluation should consider reasoning, prioritization, communication and
professional judgment.

# 10. Behavioral Evaluation

Strong behavioral answers should generally:

- Explain the situation clearly
- Identify the candidate's responsibility
- Explain actions personally taken
- Explain measurable or observable results
- Demonstrate learning

Weak answers often:

- Remain vague
- Avoid personal responsibility
- Provide no concrete example
- Provide no result
- Use excessive unrelated detail

---

# 11. Technical Answer Evaluation

Technical answers should be evaluated separately from communication.

A technically confident answer should not receive a high technical score if
the underlying concept is incorrect.

Evaluation dimensions:

- Technical correctness
- Relevance
- Completeness
- Clarity
- Communication
- Practical understanding
- Reasoning

---

# 12. Adaptive Interviewing

The next question should depend on the candidate's previous response.

If the answer is strong:

- Increase difficulty
- Explore deeper reasoning
- Ask practical follow-ups
- Test trade-offs

If the answer is partially correct:

- Ask a clarification question
- Test the missing concept
- Avoid immediately jumping to advanced material

If the answer is weak:

- Ask a simpler diagnostic question
- Identify the conceptual gap
- Provide improvement guidance after evaluation

The system should avoid repeating substantially identical questions.

---

# 13. Resume-Based Interview Preparation

When a resume is available, questions should prioritize:

- Listed skills
- Projects
- Internship experience
- Technologies
- Responsibilities
- Achievements
- Education

The system must never invent experience that is not present in the resume.

If resume information is unavailable, the system should explicitly operate
without resume-specific personalization.

---

# 14. Job Description Alignment

When a job description is available:

- Extract important skills
- Identify responsibilities
- Identify required technologies
- Identify preferred technologies
- Identify experience requirements
- Generate questions aligned with those requirements

Required skills should receive greater interview coverage.

The system should distinguish between required and preferred skills.

---

# 15. Company-Specific Preparation

When company information is supplied from an authorized source, questions
may be adapted to:

- Role expectations
- Technology stack
- Interview format
- Known competency areas
- Job description

The system must not present unverified information as official company policy.

---

# 16. Interview Difficulty

Difficulty may be represented as:

- Beginner
- Easy
- Medium
- Hard
- Expert

Difficulty should consider:

- Experience level
- Role
- Interview type
- Previous performance
- Topic complexity

Difficulty should increase gradually rather than suddenly.

---

# 17. Responsible AI Rules

The system should:

- Avoid discrimination
- Avoid judging candidates based on protected characteristics
- Avoid inventing candidate experience
- Avoid fabricated company requirements
- Clearly distinguish generated guidance from verified information
- Protect confidential candidate information
- Avoid storing unnecessary personal information
- Encourage human judgment for high-impact employment decisions

The system is an interview preparation and training tool.

It should not claim to make final hiring decisions.

---

# 18. Candidate Feedback

Useful feedback should contain:

- Overall assessment
- Technical strengths
- Technical weaknesses
- Communication strengths
- Communication weaknesses
- Missing concepts
- Specific improvement actions
- Suggested practice areas

Feedback should be actionable rather than generic.

---

# 19. Final Preparation Roadmap

At the end of an interview session, the system should identify:

1. Strong areas
2. Weak areas
3. Frequently missed concepts
4. Recommended topics
5. Recommended practice questions
6. Communication improvements
7. Suggested next interview difficulty

The roadmap should be personalized to the candidate's target role and
performance.

---

# 20. Retrieval Policy

Retrieved knowledge should be used as supporting context.

The system should prefer relevant information based on:

- Target role
- Experience level
- Interview type
- Topic
- Candidate context

Irrelevant retrieved information should not be inserted into prompts.

The system should not treat retrieved text as automatically true when it
contains conflicting or unverified information.

---

# 21. Question Generation Principles

Every generated question should:

- Match the target role
- Match the interview type
- Match the candidate's level
- Be understandable
- Test a meaningful competency
- Avoid unnecessary ambiguity
- Avoid duplicate questions
- Avoid multiple unrelated questions
- Avoid revealing the answer

---

# 22. Evaluation Principles

Every answer evaluation should:

- Consider the actual question
- Consider the candidate's actual answer
- Consider retrieved context where relevant
- Separate technical correctness from communication
- Explain the reasoning behind scores
- Avoid inflated scoring
- Avoid fabricated facts
- Produce actionable improvement advice

---

# 23. System Scope

The platform is designed to support a broad range of professional roles.

Role specialization should be driven by:

- User-provided role
- Job description
- Resume
- Retrieved knowledge
- Interview type
- Candidate experience

The architecture must not depend on a hard-coded finite list of roles.

New roles should be supported by the retrieval and prompt pipeline without
requiring changes to the core interview engine.
